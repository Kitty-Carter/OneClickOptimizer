# Positron 一键优化工具（Windows）

## 最简单的使用方法
1. 确保目标电脑已经安装 Positron；最好先打开一次。保存正在编辑的工作。
2. 将 ZIP **全部解压到同一文件夹**（可以在任意盘、任意位置，不要直接在 ZIP 内双击）。
3. 可先双击 `仅检查不修改.bat`，查看识别出的版本、实际安装路径、配置路径、支持的设置及待修改数量。
4. 双击 `一键优化.bat`。输入 Y 确认后，工具先在临时目录自检，然后自动寻找安装并优化当前 Windows 用户的 Positron。无需管理员权限，不会安装软件、联网或强制结束程序。
5. 如果出现多个安装，按提示选编号；若无法自动找到，粘贴 Positron.exe 或安装目录的完整路径。提示成功后，正常关闭并重新启动 Positron。

## 自动识别路径
- 安装位置：优先正在运行的 Positron，其次卸载注册表、系统常见安装位置、PATH、开始菜单及桌面快捷方式，以及 Windows 下载目录下名称包含 Positron 的文件夹（有限深度）。下载的安装包本身不会被运行。任意浏览器下载文件夹不等同于软件安装位置。
- 用户配置：优先显式指定路径；否则识别常见便携 data 目录和运行中进程的 `--user-data-dir`，普通安装使用当前用户 `%APPDATA%\Positron\User\settings.json`，不写死任何用户名或盘符。关闭软件后无法可靠识别自定义启动参数；请使用下方高级参数。
- 备份目录：优先 Windows Downloads 已知文件夹（包括重定向至 D/E 盘等情况），不可用时用 `%LOCALAPPDATA%\Positron-Optimizer\Backups`。不会扫描整个硬盘，也不会搜索浏览器的下载历史。

## 7 项设置（依据 PDF）
| 设置键 | 目标值 |
|---|---|
| quarto.symbols.showCodeCellsInOutline | false |
| editor.rulers | [] |
| editor.mouseWheelZoom | true |
| packages.r.installer | "base" |
| quarto.inlineOutput.enabled | false |
| console.showNotebookConsoles | true |
| positron.r.diagnostics.enabled | false（旧版检测到 enable 时改用旧键） |

新版诊断键优先，若已有旧键也同步关闭。R 诊断关闭会隐藏部分有用的错误警告；base 安装器不保证包安装更快。关闭 Quarto 内联输出改变交互体验，显示 Notebook Console 不会自动实现不同会话的对象共享。实际界面效果取决于版本、扩展、工作区配置和 R 环境。

## 备份与恢复
有实际变化才创建备份文件夹 `Positron-settings-backup-日期时间-随机编号`，窗口显示完整路径。
- `settings.before.json`：修改前原始字节（原文件存在时）。
- `settings.after.json`：修改后配置。
- `settings.did-not-exist.txt`：表示原配置不存在，此时不会伪造原始备份。
- `report.txt`：版本、配置位置、变更数量和验证结果（报告写入失败会提示）。

如需恢复，先保存工作并关闭 Positron，再将 `settings.before.json` 复制到报告所示配置位置并改名为 `settings.json`（覆盖前备份当前文件）。原本没有配置文件时，不要盲目删除之后新增的设置；可先备份再移除本工具新增的配置键。

## 安全和兼容
- 保留非目标配置的原始值文本与注释；目标值内部的注释可能随目标值替换。写出为 UTF-8 无 BOM，原始文件字节完整备份。
- 支持普通 JSON 与带注释、尾随逗号的 JSONC；拒绝错误格式或重复顶层键。已有正确设置时不重复写入。
- 检查本地安装中的配置定义/代码标识；找不到支持证据的项目会跳过并明确提示部分完成，而非假装成功。编辑器两项按 VS Code 标准配置处理。检测到代码标识不等于实际功能已验证。
- 不修改 R、Python、Quarto 安装，不安装扩展，不调整网络、系统安全策略、其他用户或项目文件。BAT 的 ExecutionPolicy Bypass 仅作用于所启动的 PowerShell 进程，不会修改全局执行策略。
- 默认用户 settings.json 不一定是活动 Profile 的配置。工作区/远程开发配置可能覆盖全局设置；如使用非默认 Profile，需用 -SettingsPath 精确指定。
- 先检测文件变化，使用同目录原子替换和备份；不兼容的文件系统可能导致安全失败。请尽量不要在运行工具的同时编辑设置。

## 高级 PowerShell 用法（在解压目录打开 PowerShell）
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Positron.ps1 -SelfTest
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Positron.ps1 -CheckOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Positron.ps1 -InstallPath 'D:\Software\Positron'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Positron.ps1 -UserDataDir 'D:\MyPositronData'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Positron.ps1 -SettingsPath 'D:\MyProfile\settings.json'
```
退出码：0=目标配置均被确认（检查模式仅检查），1=失败或取消，2=部分设置不确定或不支持。工具不保证所有版本或陌生电脑的交互式功能都已验收。

## 测试说明
核心 JSONC 合并逻辑已在 Windows PowerShell 5.1 上使用 5 个正常样本和 4 个异常样本测试通过；空数组序列化、安装清单读取、数据结构、Windows Downloads 注册表读取、临时目录原子替换与备份、新文件创建也已验证。新版完整模块已在真实 Windows 上通过自检、只读检查和隔离配置写入测试；交互界面与跨机测试尚未完成；启动 BAT 会在目标电脑运行自检（含临时目录备份和写入测试），自检失败即停止正式操作。建议首次先使用只检查模式。

开发预览补充：可使用 `-BackupRoot` 指定备份根目录；`-SettingsPath` 必须指向名为 settings.json 的文件。检测到命名 Profile 时要求显式指定。统一菜单和隔离集成测试位于项目根目录。
