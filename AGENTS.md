# AI and contributor rules

Read README, docs/MODULE-CONTRACT.md and the target module before editing. Do not add imaginary modules or claim tests ran when they did not. Never read or upload real personal settings, tokens, downloads, or logs to Git. Test with isolated fixtures and explicit paths. Never force-close an application or use administrator privileges by default. Preserve user data; report version-specific risks; make partial/failed outcomes explicit. Add tests for each change, document observed versus expected results, and preserve independent module usability. Do not silently make the repository public, alter remote history, or release as stable without evidence. Keep sources in main/modules, not permanent per-app branches.

Project positioning: curated, documented one-click application optimization presets are the core product. Discovery, backups and verification are safeguards; personal configuration cloning/sync is not the primary purpose. Distinguish workflow preferences from measured performance improvements; document rationale, applicable versions, trade-offs and evidence for every preset. Do not claim universal speedups.

For publication, use explicit path allowlists, non-force updates from the current HEAD, read back the remote commit, and keep CI, release assets and live application behavior as separate evidence. Never publish subscription files, credentials, endpoint IPs, private backups or node test records. Use ASCII release filenames, preserve old assets, verify exact ZIP bytes, and label previews truthfully.

Multi-module UX: all implemented modules have equal homepage placement, module-specific version/status, guides and independently versioned standalone release assets when published. Historical bundles retain original scope. Never label a monitor as complete or native-integrated based on a compilation or GUI smoke test; distinguish metric semantics, unavailable hardware, sampling overhead and actual Windows tests.

Feedback-control rule: define an observable baseline and setpoint; verify sensor semantics, version gates and write scope; use bounded, reversible actions; record deviations/refusals and distinguish file readback, live activation, performance and release evidence. Do not automate network changes from noisy or incomplete metrics. Measure feature-equivalent overhead where possible. Keep a known-good fallback; no automatic destructive recovery of later custom edits.

Sensor feedback rule: treat permissions, warm-up, stale data and ambiguous identities as explicit unknowns, never substitute zeros. Match process counters to PID; do not elevate just to monitor. Use a bounded background-to-UI channel, and independently test final binaries and unavailable-metric paths. Verify version-specific configuration fields in the exact upstream source rather than deleting them based on generic documentation.

Actuator feedback rule: verify recovery bytes and manifest before mutation; test partial-write recovery with fixture-only fault injection; do not treat a normal successful write as proof of rollback. Keep real user edits and unknown recovery states intact.

Network feedback rule: distinguish current routed path from per-node tests; validate local listener and use bounded HTTPS requests with certificate verification. Do not equate HTTP 403/429 with transport failure or authenticated success. Third-party exit checks require explicit user opt-in, no bulk collection, no retry after rejection, no raw IP persistence or automatic route changes. Keep upstream GPLv3 client code separate from MIT companion unless license-compliant integration is explicitly designed.

Integrated-cycle gate: freeze a baseline, use an independent worktree, preserve unrelated changes and separate released scope from the complete roadmap. A detached fixture is not live network rollback. Node screening must bound protocol, sample count, bytes and lifetime; isolate the core, protect temporary config ACL, validate listener ownership and refuse ambiguous/unsupported cases. No auto AI selection. Compare repeated ABBA blocks, not just pooled medians. Do not compile a large upstream client under severe memory pressure. Keep GPLv3 sources separate. Publish only a scope-limited preview after exact-commit CI and extracted-package verification; never call a blocked full plan complete.
